================================================================================
ESCALATION COMPLAINT SYSTEM - COMPLETE WORKFLOW & ARCHITECTURE SPECIFICATION
================================================================================

This document provides the complete, authoritative guide to the Escalation Complaint
System workflow, user roles, data routing, automated SLA escalation engine,
resolution report pipelines, HR operations, Super Admin administration, and notifications.

================================================================================
WHAT HAS BEEN UPDATED (Comprehensive Change Summary)
================================================================================

1.  DATA MODEL NORMALIZATION & OBJECTID REFERENCES
    - User Model:
        * teamLeader is an ObjectId reference to User (Team Leader).
        * department is an ObjectId reference to Department.
        * legacyTeamLeader string retained for backward compatibility.
    - Complaint Model:
        * assignedTeamLeader  -> ObjectId ref to User (TL).
        * responsibleDepartment -> ObjectId ref to Department.
        * departmentManager   -> ObjectId ref to User (Manager).
        * resolutionReports   -> Subdocument array tracking multi-tiered resolution
          reports (TL -> Manager -> HR).
        * timeline            -> Detailed chronological audit log of all actions.
        * slaPausedAt, totalPausedDuration -> Granular SLA pause tracking.
    - Category Model:
        * Linked directly to responsibleDepartment (ObjectId ref).

2.  INTELLIGENT CATEGORY-BASED COMPLAINT ROUTING
    - Automatic Routing: When a Staff member files a complaint under a Category:
        1. System queries the Category's responsible Department.
        2. System queries the Department's assigned Manager.
        3. System assigns the Staff member's active Team Leader (or Backup TL if on leave).
        4. Complaint is instantly bound to the correct TL, Department, and Manager.
        5. In-app notifications are dispatched to both TL and Department Manager.

3.  AUTOMATED TL LEAVE DETECTION & BACKUP REASSIGNMENT
    - Real-time leave check during ticket filing:
        * If the assigned TL has an approved Leave active for today's date, the
          complaint automatically routes to a designated Backup Team Leader.
        * The auto-reassignment is logged in the complaint timeline with full transparency.

4.  DEDICATED TEAM LEADER MODULE & API PIPELINE
    - Complete API suite under `/api/teamleader/*`:
        * GET  /complaints          - Filtered assigned complaints with real-time SLA metrics.
        * GET  /my-staff            - Team members with active/resolved ticket analytics.
        * GET  /complaints/:id      - Role-protected single complaint inspection.
        * PUT  /complaints/:id/status - Status transitions (In Progress, Waiting on User,
                                      Resolved, Closed) with timeline & notifications.
        * POST /complaints/:id/comment - Commenting with instant timeline logging.
        * POST /complaints/:id/resolve-report - Submits formal resolution report
                                                forwarded to Manager.
        * PUT  /complaints/:id/escalate - Manual TL-to-Manager escalation with reason.

5.  MULTI-TIER RESOLUTION REPORT & REVIEW PIPELINE
    - Resolution Reports array on Complaint:
        { solvedBy, solverName, solverRole, reportText, forwardedTo, isReviewed, createdAt }
    - Tier 1 (TL): TL drafts report -> forwardedTo = 'Manager', status = 'Resolved'.
    - Tier 2 (Manager): Manager inspects report, can add their own report, and forwards
      to HR (forwardedTo = 'HR', status = 'Pending HR Review').
    - Tier 3 (HR): HR accesses all complaints under 'Pending HR Review' via
      GET /api/hr/complaints for organizational auditing and closure.

6.  DEPARTMENT-SCOPED MANAGER OPERATIONS
    - Department Data Isolation: Managers only view and manage tickets routed to their
      assigned department.
    - Full Management Controls:
        * Reassign complaint to another TL.
        * Change status, edit priority, add managerial comments.
        * Approve resolution or formally close ticket.
        * Real-time TL Performance Monitoring (resolution rates, pending vs resolved).

7.  COMPREHENSIVE HR OPERATIONS & STAFF ONBOARDING
    - User Registration Lifecycle:
        * User self-registers -> Status: 'Pending'.
        * HR reviews pending registrations: approves, assigns Department, Team Leader,
          Designation, and Employee ID; or rejects with mandatory reason.
    - Team Leader Management:
        * HR can create Team Leaders directly (auto-generates TL001, TL002...).
        * Activate / Deactivate Team Leader status.
    - Staff & Department Management:
        * View, filter, and manage staff members.
        * Department and category metadata management.
    - Leave & Salary Modules:
        * Review and approve/reject employee leave requests.
        * Live salary, incentive, and bonus calculation engine based on attendance
          and ticket resolution performance.

8.  SUPER ADMIN GLOBAL OVERSIGHT & SLA ESCALATION ENGINE
    - Universal Visibility: Global overview of all complaints, departments, and users.
    - Stage 2 Escalation Handling: Direct intervention on double-escalated complaints.
    - Instant SLA Trigger: Manual API trigger (`/api/complaints/trigger-sla-check`)
      to immediately evaluate and escalate overdue tickets without waiting for cron.
    - Role-Based System Broadcasts: Dispatch instant broadcast notifications to all
      users or specific roles (All, Staff, Team Leader, Manager, HR).

9.  SLA AUTO-ESCALATION ENGINE (Background Cron + Test Mode)
    - 1-Minute Cron Engine with Concurrency Mutex Lock.
    - Stage 1 Escalation: Breached by TL -> Escalated to Department Manager.
    - Stage 2 Escalation: Breached by Manager -> Escalated to Super Admin.
    - SLA Pause/Resume Engine:
        * Moving ticket to 'Waiting on User' pauses SLA timer (`slaPausedAt`).
        * Returning to 'In Progress' calculates elapsed paused duration and adds to
          `totalPausedDuration`, preserving accurate SLA metrics.
    - Configurable Mode: Business hours (Mon-Fri 9AM-6PM) vs Test Mode (fast clock minutes).

10. NOTIFICATION & AUDIT ECOSYSTEM
    - Comprehensive in-app notification center for all roles:
        * Creation, assignment, status change, escalation, comments, report forwarding,
          leave approvals, and Super Admin broadcasts.
    - Mark-as-read, Mark-all-read, and Delete notification actions.
    - Immutable Audit Timeline recorded directly on each complaint.

11. MODERNIZED DESIGN SYSTEM & RESPONSIVE UI
    - Centralized CSS Design Tokens (`index.css`): Glassmorphism panels, modern
      color palettes, animated status badges, responsive dashboard layouts.
    - Unified navigation with role-tailored sidebars and interactive metric cards.


================================================================================
1. ROLES & PERMISSIONS HIERARCHY
================================================================================

The platform enforces a strict 5-tier Role-Based Access Control (RBAC) architecture:

1. STAFF (Employee)
   * Primary Duties: Raise complaints, track ticket progress, provide post-resolution
     feedback, cancel pending tickets, reopen tickets if unresolved.
   * Operations: Clock-in/out attendance, apply for leaves, view personal leave status.

2. TEAM LEADER (TL)
   * Primary Duties: Manage assigned complaints from staff, update complaint status,
     pause SLA for user input, resolve complaints, submit resolution reports to Manager,
     manually escalate tickets.
   * Operations: Manage team members, view team ticket statistics, approve/reject staff
     leaves within the team.

3. DEPARTMENT MANAGER
   * Primary Duties: Oversee department-level complaints, handle Stage 1 escalations,
     reassign tickets between TLs, review TL resolution reports, submit managerial
     reports, forward reports to HR, approve/close complaints.
   * Operations: Monitor TL performance metrics, approve/reject department staff leaves.

4. HUMAN RESOURCES (HR)
   * Primary Duties: Onboard new registrations, assign roles/departments/TLs, create
     and manage Team Leaders, review forwarded resolution reports ('Pending HR Review').
   * Operations: Department-wide leave approvals, attendance tracking, salary and
     performance-based incentive calculations.

5. SUPER ADMIN
   * Primary Duties: Highest administrative tier. Global monitoring across all departments,
     resolution of Stage 2 escalated tickets, management of departments & categories,
     system-wide announcements/broadcasts, manual execution of SLA checks.


================================================================================
2. ONBOARDING & ACCOUNT LIFECYCLE
================================================================================

Step 1: Self-Registration
        - User fills out the registration form (Name, Email, Password, Employee ID,
          Phone, Desired Role).
        - Account is created in MongoDB with status: 'Pending', isFirstLogin: true.
        - User cannot access the platform until HR approval.

Step 2: HR Verification & Assignment
        - Registration appears in HR's "Pending Registrations" view.
        - HR inspects the applicant's credentials and can:
            a. Approve:
               * Assigns Department (ObjectId).
               * Assigns Team Leader (ObjectId).
               * Assigns Designation.
               * User status becomes 'Active'.
            b. Reject:
               * Mandatory rejection reason provided.
               * User status becomes 'Inactive' with rejection reason stored.

Step 3: Direct Team Leader Creation
        - HR can directly create a Team Leader account via POST /api/hr/team-leaders.
        - System automatically provisions employee IDs (e.g. TL001, TL002).


================================================================================
3. DAILY OPERATIONS & LEAVE MANAGEMENT
================================================================================

A. Attendance Tracking
   - Users record their shift entry (Clock In) and shift exit (Clock Out).
   - System calculates working hours and attendance status ('Present', 'Late', 'Half Day').

B. Leave Application & Tiered Approval
   - Staff applies for leave (Type: Sick, Casual, Earned; Start/End Dates; Reason).
   - Status initialized to 'Pending Approval'.
   - Approval Permissions:
       * Team Leader: Can approve/reject leaves for their direct team staff.
       * Manager: Can approve/reject leaves for any staff within their department.
       * HR & Super Admin: Can approve/reject leaves globally.
   - Status updates to 'Approved' or 'Rejected' with real-time feedback to employee.

C. Intelligent TL Leave Handling during Complaint Filing
   - When a complaint is filed, the system checks if the assigned TL is on active
     approved leave for the current date.
   - If true, a Backup TL is automatically assigned, ensuring SLA timers do not stall.


================================================================================
4. COMPLAINT CREATION & AUTOMATED ROUTING
================================================================================

Step 1: Staff Raises Complaint
        - Staff selects Category, Priority (Low, Medium, High, Critical), Subject,
          and Description, with optional file attachments.
        - System generates a unique Complaint ID (e.g., CMP0012).

Step 2: Dynamic Category-to-Department Resolution
        - System retrieves Category metadata -> Finds linked Department ObjectId.
        - System retrieves Department metadata -> Finds assigned Manager ObjectId.
        - System assigns:
            * assignedTeamLeader   = Staff's assigned TL (or Backup TL if on leave)
            * responsibleDepartment = Category's Department
            * departmentManager    = Department's Manager
        - Initial Status: 'Pending'
        - Timeline Entry: "Complaint Created and Assigned to Team Leader"
        - Notifications: Dispatched to both TL and Department Manager.


================================================================================
5. TEAM LEADER RESOLUTION & ESCALATION WORKFLOW
================================================================================

A. Complaint Handling & Status Lifecycle
   - Assigned complaints appear on the TL Dashboard with live SLA countdowns.
   - Transitions:
       * 'Pending' -> 'In Progress' (TL accepts the complaint).
       * 'In Progress' -> 'Waiting on User' (Pauses SLA timer; records `slaPausedAt`).
       * 'Waiting on User' -> 'In Progress' (Resumes SLA timer; accumulates `totalPausedDuration`).
       * 'In Progress' -> 'Resolved' (TL submits resolution or formal report).
       * 'In Progress' -> 'Escalated' (TL manually escalates if unable to solve).

B. Submitting Resolution Reports
   - TL writes a detailed resolution report.
   - Action creates an entry in `complaint.resolutionReports` with `forwardedTo = 'Manager'`.
   - Status becomes 'Resolved'.
   - Manager receives notification with report details for review.

C. Manual Escalation to Manager
   - If technical complexity or resource limits prevent resolution, TL escalates ticket.
   - Status becomes 'Escalated', `escalationLevel = 1`, `escalated = true`.
   - Manager receives urgent escalation notification with the TL's reason.


================================================================================
6. AUTOMATED SLA ENGINE & 2-STAGE ESCALATION PIPELINE
================================================================================

The background escalation cron engine executes every minute. It calculates elapsed
active business minutes (excluding SLA paused time) against priority thresholds.

A. SLA Threshold Definitions
   - Production Mode (Business Hours: Mon-Fri, 9:00 AM - 6:00 PM):
       * Critical : 4 Hours  (240 mins)
       * High     : 24 Hours (1440 mins)
       * Medium   : 48 Hours (2880 mins)
       * Low      : 72 Hours (4320 mins)
   - Development / Test Mode (Wall Clock Minutes):
       * Critical : 2 Minutes
       * High     : 5 Minutes
       * Medium   : 10 Minutes
       * Low      : 15 Minutes

B. Stage 1 Auto-Escalation (Team Leader -> Manager)
   - Trigger: Elapsed business minutes >= SLA threshold AND `escalated == false`.
   - Actions:
       1. Status set to 'Escalated'.
       2. `escalated = true`, `escalationLevel = 1`.
       3. `escalatedAt = Date.now()`.
       4. Complaint timeline updated: "Automatically Escalated to Department Manager".
       5. EscalationLog record created.
       6. Notifications dispatched to Department Manager and Staff.

C. Stage 2 Auto-Escalation (Manager -> Super Admin)
   - Trigger: Complaint already at Level 1 (`escalationLevel == 1`) and elapsed time
     since Stage 1 escalation (`escalatedAt`) exceeds the SLA threshold again.
   - Actions:
       1. `escalationLevel = 2`, `escalatedToSuperAdmin = true`.
       2. Complaint timeline updated: "Automatically Escalated to Super Admin (Level 2)".
       3. EscalationLog record created.
       4. Notifications dispatched to all Super Admin users and Staff.
       5. Super Admin assumes direct intervention and resolution authority.

D. Instant SLA Evaluation Trigger
   - Super Admin can trigger immediate evaluation via POST `/api/complaints/trigger-sla-check`,
     bypassing the 60-second cron interval for rapid testing and maintenance.


================================================================================
7. MANAGER REVIEW & REPORT FORWARDING WORKFLOW
================================================================================

A. Department Oversight
   - Manager sees all active, escalated, and resolved tickets within their department.

B. Managerial Operations
   - Reassign Ticket: Reassigns ticket to a different TL (resets escalation flag).
   - Modify Priority / Status: Re-prioritize urgent issues or adjust status.
   - Direct Resolution: Manager solves ticket directly and marks it resolved.

C. Resolution Report Review & Forwarding to HR
   - Manager reviews TL's resolution report:
       * Option A: Forward TL Report -> PUT `/forward-report`.
         Marks `isReviewed = true`, updates `forwardedTo = 'HR'`, status -> 'Pending HR Review'.
       * Option B: Submit Manager Report -> POST `/resolve-report`.
         Attaches manager's report, sets `forwardedTo = 'HR'`, status -> 'Pending HR Review'.
   - HR is notified that a complaint is awaiting final organizational review.


================================================================================
8. HR AUDIT & CLOSURE WORKFLOW
================================================================================

- HR accesses all tickets marked 'Pending HR Review' via GET `/api/hr/complaints`.
- HR evaluates the resolution reports from TL and Manager.
- HR records final administrative approval, confirming compliance and customer satisfaction.


================================================================================
9. STAFF FEEDBACK & REOPEN WORKFLOW
================================================================================

A. Resolution Notification
   - Staff receives real-time notification upon ticket resolution.

B. Feedback & Rating
   - Staff rates the resolution quality from 1 to 5 stars and provides comments.
   - Feedback metrics feed into TL and Department performance scores.

C. Ticket Reopening
   - If the issue persists, Staff can click "Reopen Complaint".
   - Status reverts to 'In Progress', timeline is updated, and TL/Manager are alerted.

D. Ticket Cancellation
   - Staff can cancel any complaint in 'Pending' state if no longer relevant.


================================================================================
10. NOTIFICATION & BROADCAST SYSTEM
================================================================================

A. Automated Event Notifications
   - Stored in MongoDB `Notification` collection.
   - Triggered across lifecycle events: Ticket Creation, Status Changes, Escalations
     (Stage 1 & 2), Reassignments, Resolution Reports, and Leave Approvals.

B. Role-Based Broadcast Announcements
   - Super Admin can publish system-wide or role-targeted broadcast announcements
     (Target: All, Staff, Team Leader, Manager, HR).
   - In-app notification delivered instantly to all matching active users.

C. User Notification Center
   - View notification history.
   - Mark individual or all notifications as read.
   - Delete notifications.


================================================================================
11. SYSTEM INTEGRITY & ERROR HANDLING
================================================================================

- Database Readiness Guard: Middleware returns HTTP 503 until MongoDB connection
  is fully verified, preventing data inconsistency.
- Auto-Migration Engine: Runs on startup to normalize roles ('Employee' -> 'Staff'),
  verify reference ObjectIds, and initialize system defaults.
- Concurrency Protection: Escalation engine uses mutex locks to prevent race conditions
  during background execution.
