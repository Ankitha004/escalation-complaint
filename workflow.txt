SECTION 1: TECH STACK & PROGRAMMING LANGUAGES (WHAT & HOW IT IS USED)
================================================================================

1. FRONTEND ARCHITECTURE:
   - Language: JavaScript (ES6+), HTML5, CSS3
   - Framework & Tools: React 19 (SPA - Single Page Application), Vite (Build tool & Bundler)
   - Routing: React Router DOM v7 (Declarative nested client-side routing with role-based Route Guards)
   - State & Context: React Context API (`AuthContext`, `ThemeContext`) for centralized auth state,
     JWT decoding, role checks, and dark/light mode toggle.
   - HTTP Client: Axios (configured with interceptors to automatically append JWT bearer tokens
     and handle 401 unauthenticated redirects).
   - UI & Icons: Lucide React (feather-style clean SVG icon system), Bootstrap 5 utility grid,
     Vanilla CSS design tokens in `index.css` (glassmorphic surfaces, custom gradients, CSS variables).
   - Data Visualization: Chart.js & React-Chartjs-2 for real-time visual dashboards (doughnut,
     bar, line charts for SLA metrics, department distribution, resolution performance).
   - Rich Text / Sanitization: ReactQuill & DOMPurify to safely format and sanitize complaint descriptions.

2. BACKEND ARCHITECTURE:
   - Language: JavaScript (Node.js runtime environment)
   - Framework: Express.js (RESTful API micro-architecture)
   - Asynchronous Handling: Native ES6 Promises (`async/await`) with centralized try/catch middleware.
   - File Uploads: Multer middleware for multi-part file uploads (complaint image/document attachments).
   - Background Processing: Node-Cron running periodic automated SLA escalation evaluation every 60s.
   - Email Alerts: Nodemailer for SMTP dispatch on critical ticket events.

3. DATABASE & PERSISTENCE:
   - Database: MongoDB Atlas (Cloud NoSQL distributed document database)
   - ODM (Object Document Mapper): Mongoose v9
   - Schema Design: Normalized collections with cross-referenced ObjectIds (`ref`), indexed fields,
     and embedded subdocument arrays (`timeline`, `resolutionReports`).
   - Resiliency: Buffer timeout configured to 30,000ms, automatic connection retry logic,
     custom IPv4 DNS precedence (`ipv4first`), and 503 Service Unavailable readiness gatekeeper.

4. SECURITY & AUTHENTICATION:
   - Authentication: Stateless JSON Web Tokens (JWT) signed with HMAC-SHA256.
   - Password Hashing: Bcrypt.js with 10 salt rounds (one-way cryptographic hashing).
   - Access Control: Role-Based Access Control (RBAC) middleware verifying tokens and enforcing
     granular permissions (`protect`, `authorize('Admin', 'HR', 'Manager', 'Team Leader', 'Staff')`).
   - CORS & Sanitization: CORS middleware with explicit headers and payload size limits.

SECTION 2: COMPLETE SYSTEM WORKFLOW & LIFECYCLE
================================================================================

The platform coordinates 5 distinct user roles in a closed-loop resolution ecosystem:
[Staff] -> [Team Leader] -> [Department Manager] -> [HR] -> [Super Admin]

1. USER ONBOARDING & HR VERIFICATION LIFECYCLE:
   a. Staff / TL Registration: User registers with credentials and requested role. Account is
      initialized in MongoDB with `status: 'Pending'`.
   b. HR Approval Gate: HR accesses the Pending Registrations queue.
      - HR assigns the official Department, designated Team Leader, Designation, and Employee ID.
      - Upon HR approval, `status` becomes `'Active'`.
      - If rejected, a mandatory explanation reason is stored and account remains inactive.
   c. Direct TL Provisioning: HR can also directly provision Team Leaders with auto-incremented
      employee codes (`TL001`, `TL002`).

2. COMPLAINT FILING & INTELLIGENT AUTO-ROUTING:
   a. Staff Member initiates a complaint by choosing:
      - Category: (IT Support, Software, Facilities, Payroll, HR & Admin, Other)
      - Priority: (Low, Medium, High, Critical)
      - Subject, Detailed Description, and optional Document/Image Attachments.
   b. Intelligent System Routing:
      1. Finds Category -> Resolves responsible Department ObjectId.
      2. Finds Department -> Resolves assigned Manager ObjectId.
      3. Checks TL Leave Status: System scans `leaves` collection. If the employee's assigned TL
         has an approved leave active today, it automatically re-routes the ticket to a designated
         Backup TL!
      4. Generates unique human-readable Ticket ID (`CMP001`, `CMP002`...).
      5. Populates initial status (`Pending`), creates the first immutable timeline event, and
         dispatches real-time notifications to TL and Department Manager.

3. TEAM LEADER (TL) RESOLUTION LIFECYCLE:
   a. Real-Time Dashboard: TL inspects assigned complaints with dynamic SLA countdown timers.
   b. State Transitions:
      - 'Pending' -> 'In Progress' (TL starts work).
      - 'In Progress' -> 'Waiting on User' (Pauses SLA timer; marks `slaPausedAt`).
      - 'Waiting on User' -> 'In Progress' (Resumes SLA timer; calculates `totalPausedDuration`).
   c. Tier-1 Resolution:
      - TL drafts a formal Resolution Report (`reportText`, `solvedBy`, `forwardedTo: 'Manager'`).
      - Complaint status shifts to `'Resolved'`. Manager is alerted for quality audit.
   d. Manual Escalation:
      - If beyond TL skill or hardware limit, TL can manually escalate with reason to Stage 1.

4. AUTOMATED SLA CRON ENGINE (TWO-STAGE AUTO-ESCALATION):
   A background Node-Cron job fires every 60 seconds with concurrency mutex locking:
   - SLA Thresholds:
     * Critical: 4 hrs (Test mode: 2 mins)
     * High: 24 hrs (Test mode: 5 mins)
     * Medium: 48 hrs (Test mode: 10 mins)
     * Low: 72 hrs (Test mode: 15 mins)
   - Elapsed Time Calculation: Considers active business hours and subtracts `totalPausedDuration`.
   - Stage 1 Escalation (TL -> Manager):
     * If SLA breached and ticket not yet escalated:
     * Status becomes `'Escalated'`, `escalationLevel = 1`, `escalatedAt = Date.now()`.
     * Audit log saved to `EscalationLog`, timeline entry added, Manager and Staff alerted.
   - Stage 2 Escalation (Manager -> Super Admin):
     * If ticket has been at Level 1 and continues unresolved past secondary threshold:
     * `escalationLevel = 2`, `escalatedToSuperAdmin = true`.
     * Super Admin alerted for executive intervention.
   - Manual SLA Test Trigger: Admin can invoke `POST /api/complaints/trigger-sla-check` anytime.

5. DEPARTMENT MANAGER REVIEW & FORWARDING:
   a. Manager oversees all tickets scoped strictly to their department.
   b. Actions:
      - Reassign to different TL (resets escalation flag).
      - Adjust priority or status.
      - Inspect TL Resolution Report and forward to HR (`forwardedTo: 'HR'`, status: `'Pending HR Review'`).
      - Direct resolution: Manager can solve and mark resolved directly.

6. HR COMPLIANCE AUDIT & ORGANIZATIONAL CLOSURE:
   a. HR monitors all tickets in `'Pending HR Review'` state.
   b. HR inspects full timeline, TL reports, and Manager endorsements.
   c. HR performs final sign-off, confirming compliance and policy adherence.

7. STAFF FEEDBACK, STAR RATINGS & REOPENING:
   a. Star Rating & Feedback: Upon resolution, employee submits 1-5 star rating and comments.
      These ratings feed into performance metrics for TLs and Departments.
   b. Ticket Reopen: If problem is not adequately fixed, staff can click "Reopen". Status reverts
      to `'In Progress'`, TL is alerted, and timeline documents the reopen event.
   c. Cancellation: Staff can self-cancel a ticket if filed mistakenly before TL accepts it.

8. INTEGRATED ATTENDANCE, LEAVE & PAYROLL ENGINE:
   - Attendance: Daily Clock-In / Clock-Out timestamps with automated working hours calculation.
   - Leave System: Tiered leave approvals (TL for Team, Manager for Department, HR for Company).
   - Payroll Engine: Dynamically calculates monthly salary, deductions for unpaid leaves, and
     performance incentives based on ticket resolution speed and positive employee ratings.

SECTION 3: KEY HIGHLIGHT FEATURES (WHAT MAKES THIS PROJECT STAND OUT)
================================================================================

1. Strict Multi-Tier RBAC with Data Isolation:
   Employees, TLs, Managers, HR, and Admin have separate, tailored dashboards. A Manager cannot
   tamper with another department's complaints, enforcing data isolation.

2. SLA Pause / Resume Capability:
   Real-world IT helpdesks stall when waiting for user verification or parts. Our system pauses
   the SLA timer when status is 'Waiting on User' and accurately resumes without penalizing the TL.

3. Automated TL Leave Detection & Smart Reassignment:
   If a team leader is on approved leave today, incoming complaints automatically route to a
   designated Backup TL, ensuring zero SLA SLA downtime.

4. Two-Stage Auto-Escalation Architecture:
   Automated progression from TL (Level 1) to Manager and finally to Super Admin (Level 2) with
   full audit trail in MongoDB.

5. Immutable Complaint Timeline:
   Every status transition, comment, escalation, and report creates an immutable timeline entry
   with timestamp and actor credentials.

6. Live Performance Metrics & Analytics:
   Interactive Chart.js visualizations for SLA breach rates, departmental resolution velocity,
   and staff feedback scores.

SECTION 4: COMPREHENSIVE VIVA QUESTIONS & DEFENSE ANSWERS
================================================================================

Q1: What is the architecture of your project?
A1: "The project uses the MERN stack (MongoDB, Express.js, React, Node.js) following a RESTful
     Single Page Application (SPA) architecture. The frontend is built with React 19 and Vite,
     communicating with an Express/Node.js backend via JSON REST APIs over Axios. Data is stored
     in MongoDB Atlas using Mongoose ODM with normalized schemas and ObjectId relationships.
     Stateless authentication is handled using JWT (JSON Web Tokens) with RBAC middleware."

Q2: Why did you choose MongoDB instead of a relational database like MySQL?
A2: "1. Schema Flexibility: Complaints require dynamic, deeply nested subdocuments like audit
        timelines and multi-tier resolution reports (TL -> Manager -> HR), which naturally fit
        MongoDB's BSON document model.
     2. Cloud Scalability: MongoDB Atlas provides built-in sharding, replica sets, and easy cloud
        clustering.
     3. Fast Iteration & Developer Velocity: Working with JSON natively across frontend (React)
        and backend (Node.js) eliminates impedance mismatch."

Q3: How does your SLA Escalation Engine work technically?
A3: "We implemented a background cron job using `node-cron` that runs every 60 seconds.
     It queries all un-resolved complaints and calculates the elapsed business time against priority
     thresholds (Critical: 4h, High: 24h, Medium: 48h, Low: 72h).
     If a complaint breaches its threshold, it triggers Stage 1 escalation (TL to Manager), logs to
     `EscalationLog`, writes to the complaint timeline, and dispatches in-app notifications. If the
     Manager does not act, a secondary breach triggers Stage 2 escalation to the Super Admin."

Q4: How do you prevent SLA timers from unfairly penalizing staff when waiting for the user?
A4: "We built an SLA Pause/Resume feature. When a TL changes the ticket status to 'Waiting on User',
     the system records the current timestamp in `slaPausedAt`. When the ticket reverts back to
     'In Progress', the system calculates `Date.now() - slaPausedAt` and accumulates it into
     `totalPausedDuration`. The escalation calculation subtracts `totalPausedDuration` from the
     total elapsed time."

Q5: How is security and Role-Based Access Control (RBAC) enforced?
A5: "On the backend, every incoming request passes through an authentication middleware (`protect`)
     that verifies the JWT bearer token signature and decodes the user payload.
     Then, an authorization middleware (`authorize('Admin', 'Manager', ...)` checks if the user's
     role has permission for that specific endpoint. On the frontend, React Router wraps protected
     pages in `<ProtectedRoute allowedRoles={[...]} />`, redirecting unauthorized users."

Q6: How do passwords stay secure?
A6: "Passwords are never stored in plaintext. We use `bcryptjs` with 10 salt rounds to hash passwords
     before persisting them into MongoDB via a Mongoose pre-save hook. Even if database records
     were inspected, passwords cannot be reversed."

Q7: What happens if an assigned Team Leader is on leave when a complaint is created?
A7: "Our system has an automated Leave-Aware Routing mechanism. During complaint creation, the backend
     queries the `leaves` collection to see if the staff member's TL has an approved leave for
     today's date. If so, it automatically routes the complaint to a designated Backup TL and notes
     this in the ticket timeline."

Q8: How did you handle category icons and UI clutter?
A8: "We normalized categories into 6 core industry standard categories (IT Support, Software,
     Facilities, Payroll, HR & Admin, Other). On the React frontend, Lucide-React SVG icons are
     dynamically bound to each category (e.g., Laptop for IT, Code for Software, Building for
     Facilities). In the database, categories link directly to responsible departments."

Q9: What error-handling mechanisms are present in the backend?
A9: "1. Centralized Error Middleware: Captures uncaught route errors and returns consistent JSON
        error responses (`{ message, stack }` in development).
     2. 503 Readiness Gatekeeper: Prevents queries from failing during MongoDB Atlas connection/TLS
        handshakes.
     3. Auto-Reconnect: Mongoose listens to `disconnected` events and automatically executes an
        exponential backoff reconnection attempt."
